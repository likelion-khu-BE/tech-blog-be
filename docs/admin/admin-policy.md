# Admin 권한 정책

## 개요

admin 권한, 기수 종료, 회장 권한 이양, 글/댓글 관리 정책을 정리했습니다.

기존에는 회장, 부회장, 세션장을 포함한 운영진 전체가 동일한 admin 권한을 가지는 방향을 생각했지만, admin 권한에 기수 종료, 권한 부여/해제, 멤버 관리, 글/댓글 관리 등 중요한 기능이 포함될 수 있어 권한을 분리하는 것이 더 안전하다고 판단했습니다.

---

## 결정 사항

1. 권한은 `PRESIDENT`, `ADMIN`, `MEMBER`로 구분합니다.
2. 최초 회장은 DB에서 직접 `PRESIDENT`로 지정합니다.
3. `PRESIDENT`만 admin 권한을 부여/해제할 수 있습니다.
4. `ADMIN`은 admin 페이지에 접근할 수 있지만, 다른 사용자를 admin으로 지정하거나 admin 권한을 해제할 수 없습니다.
5. 자기 자신의 admin 권한은 해제할 수 없도록 제한합니다.
6. 기수 종료는 자동 처리하지 않고 `PRESIDENT`가 직접 실행합니다.
7. 기수 종료 시 일반 `MEMBER`와 기존 `ADMIN`은 `EXPIRED` 상태로 변경합니다.
8. 기존 `ADMIN`의 admin 권한은 기수 종료 시 제거됩니다.
9. `PRESIDENT`도 기수 종료 후 상태값은 `EXPIRED`로 변경하되, `PRESIDENT` 권한은 유지합니다.
10. `PRESIDENT` 권한 이양은 기수 종료 이후에만 가능합니다.
11. 기존 회장은 다음 회장에게 권한을 넘긴 이후 별도 관리자 권한을 유지하지 않습니다.
12. 비상 상황이 발생한 경우에는 DB 관리자가 직접 권한을 복구하거나 수정합니다.
13. 멤버는 실제 삭제하지 않고 상태값 변경으로 관리합니다.
14. 글/댓글은 즉시 삭제하지 않고 숨김 처리합니다.
15. 숨김 처리 후 24시간이 지나면 관리자가 수동 삭제할 수 있습니다.
16. 작성자는 본인의 글/댓글이 숨김 상태인지 확인할 수 있습니다.
17. admin은 팀원별 점수 산정 내역과 총점을 조회할 수 있습니다.
18. 점수 직접 수정 기능은 제공하지 않습니다. 점수 오류 발생 시 DB 관리자가 직접 수정합니다.
19. admin 권한 부여/해제, 기수 종료, 글/댓글 숨김 및 삭제 등 주요 관리자 작업은 로그로 남기는 방향을 고려합니다.

---

## 결정 이유

### 1. 모든 운영진에게 동일한 admin 권한을 주는 것은 위험함

처음에는 회장, 부회장, 세션장 등 운영진 전체가 admin 권한을 가지는 방향을 생각했습니다.

하지만 admin 권한에는 단순 관리 기능뿐만 아니라 다음과 같은 중요한 기능이 포함될 수 있습니다.

- admin 권한 부여/해제
- 기수 종료
- 멤버 상태 변경
- 멤버 팀 이동
- 글/댓글 관리
- 점수 산정 내역 조회

이 권한을 모든 운영진이 동일하게 가지면 권한 범위가 과도하게 커질 수 있습니다.

따라서 회장 권한인 `PRESIDENT`와 일반 관리자 권한인 `ADMIN`을 분리하고, 서비스 전체에 영향을 주는 기능은 `PRESIDENT`만 수행할 수 있도록 정리했습니다.

---

### 2. admin 권한 부여/해제는 회장만 수행하는 것이 안전함

admin 권한을 가진 모든 사용자가 다른 사용자를 admin으로 지정할 수 있으면, admin 권한이 의도보다 넓게 퍼질 수 있습니다.

따라서 admin 페이지 접근은 `ADMIN`도 가능하게 하되, admin 권한 부여/해제는 `PRESIDENT`만 가능하도록 제한합니다.

또한 자기 자신의 admin 권한을 직접 해제할 수 없도록 제한합니다.

이는 실수로 모든 관리자 권한이 사라지는 상황을 방지하기 위함입니다.

---

### 3. 기수 종료는 자동 처리보다 회장이 직접 처리하는 것이 적절함

기수 종료를 연도 기준으로 자동 처리할 수도 있지만, 실제 운영에서는 해커톤이나 행사 일정이 다음 해 1월까지 이어질 수 있습니다.

따라서 단순히 연도가 바뀌었다고 자동으로 권한을 종료하는 방식은 위험할 수 있습니다.

기수 종료 시점은 운영 상황에 따라 달라질 수 있으므로, `PRESIDENT`가 직접 기수 종료 버튼을 눌러 처리하는 방식이 적절하다고 판단했습니다.

---

### 4. 회장 권한 이양은 기수 종료 이후에만 가능해야 함

회장 권한은 서비스 전체 권한 구조와 연결됩니다.

따라서 아무 시점에나 회장 권한을 이양할 수 있으면 운영 상태가 꼬일 수 있습니다.

기수 종료 후 기존 회원과 운영진 권한을 정리한 뒤, 다음 회장에게 `PRESIDENT` 권한을 넘기는 흐름이 더 명확하다고 판단했습니다.

기존 회장은 다음 회장에게 권한을 넘긴 이후 별도 관리자 권한을 유지하지 않습니다.

다만 다음 회장 계정에 문제가 생기거나 권한 이양 과정에서 오류가 발생하는 등 비상 상황이 발생하면 DB 관리자가 직접 권한을 복구하거나 수정하는 방식으로 처리합니다.

---

### 5. 멤버는 실제 삭제하지 않고 상태값으로 관리하는 것이 안전함

멤버를 DB에서 실제로 삭제하면 해당 멤버가 작성한 글, 댓글, 점수 기록, 활동 기록과의 연결이 깨질 수 있습니다.

따라서 멤버 삭제는 실제 delete가 아니라 상태값 변경 방식으로 처리합니다.

기수 종료 또는 활동 종료 시에는 회원 상태를 `EXPIRED`로 변경합니다.

---

### 6. 글/댓글은 즉시 삭제하지 않고 숨김 처리 우선

관리자가 글/댓글을 바로 삭제할 수 있게 하면 실수로 중요한 내용을 삭제할 가능성이 있습니다.

따라서 글/댓글은 먼저 숨김 처리하고, 숨김 처리 후 24시간이 지난 뒤 관리자가 수동으로 삭제할 수 있도록 정리했습니다.

작성자는 본인의 글/댓글이 숨김 상태인지 확인할 수 있습니다.

---

### 7. 점수 직접 수정 기능은 제외

점수는 민감한 정보이기 때문에 admin 페이지에서 직접 수정할 수 있게 하면 추후 분쟁이나 실수 가능성이 있다고 판단했습니다.

따라서 admin은 팀원별 점수 산정 내역과 총점만 조회할 수 있고, 점수 직접 수정 기능은 제공하지 않습니다.

점수 오류가 발생한 경우에는 DB 관리자가 직접 확인 후 수정하는 방식으로 처리합니다.

---

## 권한별 기능

### PRESIDENT

회장 권한입니다. 서비스 내 최상위 관리자이며, 일반 admin보다 높은 권한을 가집니다.

**가능한 기능**

- admin 권한 부여
- admin 권한 해제
- 기수 종료 처리
- 다음 회장에게 `PRESIDENT` 권한 이양
- admin 페이지 접근
- 멤버 상태 변경
- 멤버 팀 이동
- 글/댓글 숨김 처리
- 숨김 처리 후 24시간이 지난 글/댓글 수동 삭제
- 팀원별 점수 산정 내역 및 총점 조회

---

### ADMIN

부회장, 세션장 등 운영진에게 부여되는 권한입니다.

**가능한 기능**

- admin 페이지 접근
- 멤버 상태 변경
- 멤버 팀 이동
- 글/댓글 숨김 처리
- 숨김 처리 후 24시간이 지난 글/댓글 수동 삭제
- 팀원별 점수 산정 내역 및 총점 조회

**불가능한 기능**

- 다른 사용자에게 admin 권한 부여
- 다른 사용자의 admin 권한 해제
- 기수 종료 처리
- `PRESIDENT` 권한 이양
- 점수 직접 수정

---

### MEMBER

현재 기수의 일반 회원입니다.

**가능한 기능**

- 글 작성
- 본인 글 수정
- 댓글 작성
- 본인 댓글 수정
- 현재 기수 활동 기능 사용

---

## 최초 PRESIDENT 지정 방식

서비스 최초 운영 시에는 아직 `PRESIDENT` 권한을 가진 사용자가 존재하지 않습니다.

따라서 최초 회장 계정은 DB에서 직접 `PRESIDENT` 권한을 부여합니다. 이 작업은 최초 1회만 수행합니다.

이후부터는 `PRESIDENT` 권한을 가진 사용자가 admin 페이지에서 운영진에게 `ADMIN` 권한을 부여합니다.

---

## admin 권한 부여/해제 정책

admin 권한 부여 및 해제는 `PRESIDENT`만 수행할 수 있습니다.

`ADMIN` 권한을 가진 사용자는 admin 페이지에는 접근할 수 있지만, 다른 사용자를 admin으로 지정하거나 기존 admin 권한을 해제할 수 없습니다.

또한 자기 자신의 admin 권한은 직접 해제할 수 없도록 제한합니다. 이는 실수로 모든 관리자 권한이 사라지는 상황을 방지하기 위함입니다.

---

## 기수 종료 정책

기수 종료는 자동 처리하지 않고, `PRESIDENT`가 직접 기수 종료 버튼을 눌러 처리합니다.

**기수 종료 시 처리 방식**

- 일반 `MEMBER` → 상태값 `EXPIRED`로 변경
- 기존 `ADMIN` → 상태값 `EXPIRED`로 변경 + admin 권한 제거
- `PRESIDENT` → 상태값 `EXPIRED`로 변경, `PRESIDENT` 권한은 유지

기수 종료 후에는 회장만 권한을 유지하고, 기존 운영진의 admin 권한은 제거됩니다.

---

## PRESIDENT 권한 이양 정책

`PRESIDENT` 권한 이양은 기수 종료 이후에만 가능합니다.

**이양 흐름**

1. 기존 `PRESIDENT`가 기수 종료 처리
2. 일반 회원 및 기존 admin 상태 정리
3. 다음 회장 계정 선택
4. 다음 회장에게 `PRESIDENT` 권한 이양
5. 기존 회장의 `PRESIDENT` 권한 제거

기존 회장은 다음 회장에게 권한을 넘긴 이후 별도의 관리자 권한을 유지하지 않습니다.

비상 상황(다음 회장 계정 문제, 이양 오류 등) 발생 시 DB 관리자가 직접 권한을 복구하거나 수정합니다.

---

## 멤버 관리 정책

멤버는 DB에서 실제로 삭제하지 않습니다. 멤버를 실제 삭제하면 해당 사용자가 작성한 글, 댓글, 점수 기록, 활동 기록과의 연결이 깨질 수 있기 때문입니다.

따라서 멤버 삭제 대신 상태값 변경 방식으로 처리합니다.

**상태값 정의**

| 상태 | 의미 |
|------|------|
| `PENDING` | 가입 승인 대기 |
| `ACTIVE` | 현재 활동 회원 |
| `REJECTED` | 가입 반려 |
| `EXPIRED` | 가입 신청 후 7일 내 미승인으로 만료 |
| `ALUMNI` | 기수 종료 또는 활동 만료 회원 (졸업생) |

멤버 상태가 `ALUMNI`로 변경되면 현재 기수 활동 권한은 제한됩니다.

---

## 글/댓글 관리 정책

관리자는 글/댓글을 즉시 삭제하지 않고 먼저 숨김 처리합니다.

숨김 처리된 글/댓글은 일반 사용자에게 보이지 않습니다. 작성자는 본인의 글/댓글이 숨김 상태인지 확인할 수 있습니다.

숨김 처리 후 24시간이 지나면 관리자가 수동으로 삭제할 수 있습니다.

**처리 흐름**

1. 관리자가 글/댓글 숨김 처리
2. 작성자는 숨김 상태 확인 가능
3. 숨김 처리 후 24시간 경과
4. 관리자가 필요 시 수동 삭제

삭제는 자동으로 처리하지 않고 관리자가 직접 수행합니다.

---

## 점수 관리 정책

admin 페이지에서 점수 직접 수정 기능은 제공하지 않습니다.

대신 admin은 각 팀원의 점수 산정 내역과 총점을 조회할 수 있습니다.

**조회 항목 예시**

- 작성한 글 수
- 작성한 댓글 수
- 활동별 반영 점수
- 총점

점수가 제대로 반영되지 않는 문제가 발생한 경우에는 DB 관리자가 직접 확인 후 수정합니다.

---

## 관리자 작업 로그

admin 권한 부여/해제, 기수 종료, 글/댓글 숨김 및 삭제 등 주요 관리자 작업은 로그로 남기는 방향을 고려합니다.

**테이블 구조 (안)**

```sql
CREATE TABLE admin_action_logs (
    id             BIGSERIAL    PRIMARY KEY,
    actor_user_id  BIGINT       NOT NULL REFERENCES users(id),
    target_type    TEXT         NOT NULL,
    target_id      TEXT         NOT NULL,
    action_type    TEXT         NOT NULL,
    before_value   TEXT,
    after_value    TEXT,
    reason         TEXT,
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

**target_type 예시**

| 값 | 대상 |
|----|------|
| `USER` | 사용자 |
| `POST` | 게시글 |
| `COMMENT` | 댓글 |
| `GENERATION` | 기수 |

**action_type 예시**

| 값 | 의미 |
|----|------|
| `GRANT_ADMIN` | admin 권한 부여 |
| `REVOKE_ADMIN` | admin 권한 해제 |
| `END_GENERATION` | 기수 종료 |
| `TRANSFER_PRESIDENT` | 회장 권한 이양 |
| `CHANGE_MEMBER_STATUS` | 멤버 상태 변경 |
| `MOVE_MEMBER_TEAM` | 멤버 팀 이동 |
| `HIDE_POST` | 글 숨김 처리 |
| `HIDE_COMMENT` | 댓글 숨김 처리 |
| `DELETE_POST` | 글 삭제 |
| `DELETE_COMMENT` | 댓글 삭제 |

---

## 기수 종료 시 상태 변경

기수 종료 처리 시 모든 `ACTIVE` 상태의 일반 `MEMBER` 및 `ADMIN` 계정은 `ALUMNI` 상태로 변경됩니다.

`EXPIRED`는 "가입 신청 후 7일 내 미승인으로 만료된 계정"에만 사용하며, 기수 종료와 관련된 상태는 `ALUMNI`로 구분합니다.
